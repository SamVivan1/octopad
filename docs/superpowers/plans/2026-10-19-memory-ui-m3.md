# Post-M2 Fix Plan — Memory, Layout, Branding, and M3

Date: 2026-10-19
Status: approved by the project owner
Predecessor: `docs/superpowers/plans/2026-10-18-tauri-rewrite-m2.md`

## Why this plan exists

M2 shipped with unit tests, type-checks and CI builds green, but the owner ran
the app and found four problems the automation could never have caught:

1. **Memory.** Fresh load reported ~500 MB versus <100 MB for the legacy Python
   app. This violates the memory budget in the design spec.
2. **Layout.** The key grid and the action inspector are stacked vertically; the
   intended layout is buttons left, actions right.
3. **No Home Assistant settings.** HA is M3 scope and never existed in the UI.
4. **Everything is free text.** No device/app/audio/HA discovery: the user types
   app names, audio sinks and HA entities by hand. All four pickers exist in the
   Python apps.
5. **No logo.** Tauri default icons are still in place; the real artwork already
   exists in `linux-app/`.

A fifth item surfaced while planning and belongs to M3: **pressing a button
currently does nothing.** `M2` logs the event; no action is executed. That is the
single largest gap between the new app and the app it replaces.

## Decisions taken (owner, 2026-10-19)

| Topic | Decision |
| --- | --- |
| Memory | Optimize first and measure PSS per process. A 100 MB total budget is acknowledged as unrealistic for a webview app; the working target is ~150–200 MB PSS. |
| Order | Fix the UI (layout + logo) before starting M3. |
| Home Assistant | REST only, exactly like the Python apps: URL/token in settings, connection test, entity picker from `/api/states`, service call. No WebSocket. |
| Console | Keep the free-text console as a debug tool; it is not the primary interaction path. |

## Phase 0 — Memory

**Protocol (used for both apps, so the comparison is fair).** Fresh start, window
shown, idle for 5 s, three runs. Record **PSS and RSS per process** plus the
process count:

```bash
for p in $(pgrep -f octopad-tauri); do
  echo "== $p"; tr '\0' ' ' < /proc/$p/cmdline; echo
  grep -E "^(Rss|Pss):" /proc/$p/smaps_rollup
done
```

RSS sums double-count pages shared between the Tauri/WebKit processes; PSS is the
honest number. The Python app runs in one process, so its PSS and RSS are nearly
equal — that difference is why a naive RSS-sum comparison is unfair.

**Implementation.** Set the WebKit/GL environment variables in Rust **before**
Tauri initialises the webview (top of `run()` in `app-tauri/src-tauri/src/lib.rs`,
or `main.rs` — whichever runs first):

- `WEBKIT_DISABLE_DMABUF_RENDERER=1` — the DMA-BUF/GPU render path is the single
  largest allocator in WebKitGTK.
- `WEBKIT_DISABLE_COMPOSITING_MODE=1` — removes the extra compositing surfaces.
- `LIBGL_ALWAYS_SOFTWARE=1` — keeps the GPU process from allocating driver
  buffers.

Each flag is measured individually before keeping it, because disabling
compositing can cause visible artefacts. A flag that does not measurably reduce
PSS is removed rather than carried.

**Acceptance:** PSS recorded in `app-tauri/memory-notes.md` for both apps. If the
optimised Tauri app still exceeds ~200 MB PSS, stop and report to the owner with
the numbers and the architecture trade-off — do **not** silently revise the
budget in the spec.

## Phase 1 — Two-column layout

`ButtonsPage.svelte` becomes a two-column region: the 8-key grid on the left, the
action inspector on the right, each scrolling independently, collapsing to a
single column below ~900 px. Drive it from new `--shell-*` layout tokens in
`src/app.css` rather than ad-hoc rules. Contract test asserts both panels are
present and that the grid precedes the inspector in DOM order.

## Phase 2 — Real logo and stateful tray icons

Source artwork already exists and is used as-is:

- `linux-app/octopad.svg`, `linux-app/octopad.png`
- `linux-app/tray-icons/hicolor/{22,24,32,48,64,128}/apps/octopad-tray.png`,
  `octopad-tray-checking.png`, `octopad-tray-off.png`

Work: render the SVG to the required PNG sizes plus `icon.ico`/`icon.icns`,
replace `app-tauri/src-tauri/icons/*`, bundle the three tray states as Tauri
resources, and update the tray icon from the existing serial/BLE status events
(connected / checking / off) instead of always showing one static icon. Desktop
entry `Name`/`Icon` and the window title follow the same branding.

A Rust unit test maps status events to the expected tray asset so the mapping
cannot silently regress.

## Phase 3 — M3

Split so no single milestone is unmanageable.

**M3.1 — Action execution (the missing core).** A dispatcher turns a button press
into the configured action list, in order, through the existing serialized edit
queue semantics: keyboard shortcuts, typed text, media keys, scripts, system
actions, `mode_toggle`, and action chains with `delay`. Per resolved parity
decision 1, a failed action does not abort the chain and is reported in the
console. Platform input goes through `enigo` or the native API on each OS.

**M3.2 — Discovery and pickers.** Port the Python implementations:

| Feature | Python source | New backend command |
| --- | --- | --- |
| Installed apps | `linux-app/app_scanner.py:73` `get_installed_apps()` | `list_apps()` |
| Audio outputs | `linux-app/system_actions.py:273` `list_audio_sinks()` | `list_audio_outputs()`, `set_default_audio_output()` |
| Home Assistant | `linux-app/home_assistant.py:223` `HomeAssistantClient` | `ha_entities()`, `ha_services()`, `ha_call_service()`, `ha_status` |

Linux audio uses `wpctl`/`pactl`; Windows uses `IPolicyConfig` through the
`windows` crate. HA adds a settings section (URL, token, connection test,
entity count). Every free-text field that has a discoverable list becomes a
picker; the console remains for debugging.

**M3.3 — Presets and profiles.** Built-in preset gallery, user presets, and
profile import/export (the legacy config importer already exists).

## Scope boundaries

- No new action types beyond the 12 in the current schema.
- No Home Assistant WebSocket.
- No macOS, no auto-update, no code signing, no firmware changes.
- The legacy Python apps keep working until M5.

## Review focus

- **Memory measurement honesty:** report PSS *and* RSS *and* process count; never
  compare a summed RSS against a single-process number.
- **Env var placement:** the flags must be set before webview initialisation or
  they silently do nothing.
- **Layout regressions:** the inspector must stay usable at narrow widths and the
  grid must keep at least two columns.
- **Tray state correctness:** the icon must reflect the real connection state, not
  a cached value, and must not leak file handles by recreating the icon on every
  event.
- **Execution correctness:** an action chain runs in order, stops only where the
  action list ends, and a failure never aborts the remaining actions.
- **Picker failure paths:** an empty list (no Bluetooth adapter, no `wpctl`,
  unreachable HA) must render a clear message, never a crash or a silent
  fallback to free text.
